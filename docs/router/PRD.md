# PRD: 라우터 + 게이트웨이

- 담당: 팀원C · 브랜치: `feat-router`
- 먼저 읽을 문서: `docs/PRD.md`, `docs/ARCHITECTURE.md`(계약 1~5 전부), `docs/ADR.md`

## 목표
고객 메시지를 마스킹하고, 9개 주제로 분류해 올바른 에이전트·되묻기·미지원 안내로 보낸다. 모든 모델 호출이 한 곳을 거치며 입력이 기록되게 한다.

## 담당 범위
1. **게이트웨이** — `POST /api/chat`, 세션(대화 이력 마스킹본, 되묻기 대기 질문), 응답 분기(answer / clarify / unsupported)
2. **마스킹** — 주민번호·카드번호·계좌번호·전화번호·주소·금액을 토큰(`[계좌번호_1]` 등)으로 치환하고 `mask_map`을 돌려준다
3. **모델 호출 모듈** — `llm.generate()`, 호출마다 `logs/model_inputs.jsonl` 기록
4. **라우터** — `cs-router` 모델 학습(9개 주제 분류)과 `router.classify()`
5. **공통 기반** — `main.py`, `agents/base.py`, 세 에이전트 스텁, `training/common`(은행 필터 + source_id 분할)

## 사용자 스토리
1. 고객이 "내 잔액 얼마야?"를 보내면 잔액조회 에이전트로 간다.
2. 고객이 "대출 잔액이랑 이자 얼마 남았어요?"를 보내면 "어느 쪽을 먼저 도와드릴까요?"와 선택지(대출문의 / 이자·연체)를 받는다.
3. 고객이 환전을 물으면 "해당 주제는 아직 지원하지 않습니다"와 상담원 연결 안내를 받는다.
4. PM은 `logs/model_inputs.jsonl`을 열어 계좌번호·주민번호 원본이 없는지 확인한다.

## 인수 기준 (이 영역 책임)
- 라우팅: PM 고정 테스트 문의에서 올바른 에이전트 또는 미지원 안내 비율 90% 이상
- 복합 문의는 되묻기로 처리(한쪽으로 보내면 불합격)
- 마스킹: 고정 시나리오(예: "제 계좌 110-1234-5678이고 주민번호 900101-1234567인데 잔액 알려줘") 입력 후 모델 입력 로그에 원본 값 0건
- 첫 응답 10초 이내에서 라우터가 차지하는 시간을 측정해 보고한다
- `pytest backend/tests/router backend/tests/gateway backend/tests/masking backend/tests/llm` 통과

## 제외
- 미지원 6개 주제의 답변 생성, 실제 상담원 연결, 인증, 세션 영속화(DB)

## 확인 필요
- **베이스 모델 크기**: 4개 모델 동시 적재 + 10초 기준으로 벤치마크해 팀에 공유한다(공통 ADR-005). 게이트: 에이전트 학습 착수 전.
- **데이터셋 실제 구조**: 원본을 받으면 필드명·폴더 구조를 확인하고, 가정과 다르면 공통·영역 문서를 고친다. 게이트: 공통 분할 전(`docs/PRD.md` 확인 필요).
