# ADR: 라우터 + 게이트웨이

> 공통 결정(ADR-001~008)은 `docs/ADR.md`를 따른다.

### RT-001: 라우터는 파인튜닝한 생성형 분류기 (주제 코드 텍스트 출력)
**결정**: 공통 베이스 모델을 QLoRA로 학습해 주제 코드 하나를 출력하게 한다. 서빙은 다른 모델과 같은 Ollama를 쓴다.
**이유**: PRD 제약상 라우터도 로컬 파인튜닝 모델이다. 추론 스택을 Ollama 하나로 유지한다.
**트레이드오프**: 분류 전용 모델(인코더 + 분류 헤드)보다 느리고 확률값을 바로 쓰기 어렵다. 10초 기준 안에서 라우터에 쓸 수 있는 시간을 측정한다.

### RT-002: 복합 문의는 키워드 규칙으로 판별한다 (2026-09-28 확정)
**결정**: 라우터 모델은 주제 1개만 출력한다. `classify()`가 지원 주제(balance·loan·interest)별 키워드 그룹을 검사해 2개 이상 걸리면 모델 출력 대신 그 주제들을 `topics`로 돌려준다(→ 게이트웨이가 되묻기). 1개 이하면 모델 출력을 쓴다.
**이유**: 데이터셋 라벨은 상담마다 1개라서 다중 코드 학습에는 합성 데이터가 필요하다. 키워드 규칙은 결과가 결정적이라 PM 시나리오를 그대로 테스트로 만들 수 있다.
**트레이드오프**: "대출 이자 얼마예요?"처럼 한 주제 질문도 되물을 수 있다. 턴이 하나 늘지만 불합격 조건(한쪽으로만 보냄)은 피한다. 키워드 표와 예외는 테스트로 확정하며, 최소한 다음을 통과해야 한다.
- "대출 잔액이랑 이자 얼마 남았어요?" → `loan`, `interest` ("대출 잔액"은 계좌 잔액이 아니다)
- "대출 이자가 왜 이렇게 많이 나왔어요?" → `loan`, `interest`
- "내 잔액 얼마야?" → 모델 출력(`balance`) 그대로

### RT-003: 세션은 메모리 dict
**결정**: `session_id → {history, pending}`을 프로세스 메모리에 둔다.
**이유**: 데모 1대, 사용자 1명이다. 재시작하면 대화가 사라져도 된다.
**트레이드오프**: 여러 프로세스나 재시작 뒤에는 세션이 유지되지 않는다.

### RT-004: 모델 입력 로그는 JSONL 한 파일
**결정**: `llm.generate()`가 호출마다 `logs/model_inputs.jsonl`에 `{ts, model, messages}`를 추가한다.
**이유**: PM이 인수 때 파일을 열어 원본 개인정보가 없는지 직접 확인한다(PRD 인수 기준 5).
**트레이드오프**: 로그가 계속 커진다. 데모 전에 수동으로 지운다. 로그 파일도 git에 올리지 않는다.
