# ADR: 라우터 + 게이트웨이

> 공통 결정(ADR-001~008)은 `docs/ADR.md`를 따른다.

### RT-001: 라우터는 파인튜닝한 생성형 분류기 (주제 코드 텍스트 출력)
**결정**: 공통 베이스 모델을 QLoRA로 학습해 주제 코드 하나(또는 쉼표로 구분한 여러 개)를 출력하게 한다. 서빙은 다른 모델과 같은 Ollama를 쓴다.
**이유**: PRD 제약상 라우터도 로컬 파인튜닝 모델이다. 추론 스택을 Ollama 하나로 유지한다.
**트레이드오프**: 분류 전용 모델(인코더 + 분류 헤드)보다 느리고 확률값을 바로 쓰기 어렵다. 10초 기준 안에서 라우터에 쓸 수 있는 시간을 측정한다.

### RT-002: 복합 문의 판별 — 미결정 (이 영역 첫 작업에서 확정)
**후보**:
- (a) 학습 데이터에 두 주제 문장을 합성한 예시를 넣어 "balance,interest"처럼 여러 코드를 출력하게 학습한다
- (b) 한 개만 출력하게 학습하고, 게이트웨이 키워드 규칙("잔액"+"이자" 등)으로 복합을 판별한다
**판단 기준**: PM 고정 시나리오의 복합 문의를 되묻기로 처리하는 비율, 구현 단순성
**참고**: 데이터셋 라벨은 상담마다 1개라서, (a)를 택하면 합성 데이터가 필요하다.

### RT-003: 세션은 메모리 dict
**결정**: `session_id → {history, pending}`을 프로세스 메모리에 둔다.
**이유**: 데모 1대, 사용자 1명이다. 재시작하면 대화가 사라져도 된다.
**트레이드오프**: 여러 프로세스나 재시작 뒤에는 세션이 유지되지 않는다.

### RT-004: 모델 입력 로그는 JSONL 한 파일
**결정**: `llm.generate()`가 호출마다 `logs/model_inputs.jsonl`에 `{ts, model, messages}`를 추가한다.
**이유**: PM이 인수 때 파일을 열어 원본 개인정보가 없는지 직접 확인한다(PRD 인수 기준 5).
**트레이드오프**: 로그가 계속 커진다. 데모 전에 수동으로 지운다. 로그 파일도 git에 올리지 않는다.
