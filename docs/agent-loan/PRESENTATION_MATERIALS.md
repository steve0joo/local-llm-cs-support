# 발표 자료용 정리: 대출문의 모델 v1 → v4 (2026-09-30)

PPT를 만들 때 바로 가져다 쓸 수 있게 이야기 흐름, 수치, 실제 응답 예시, 한계를 모았다. 근거는 `MODEL_HISTORY_v1_v4.md`, `EVAL_RESULT_v4.md`, `ADR.md`(LN-007, LN-008)이고 수치는 모두 거기서 온 것이다. 응답 예시는 평가 원문(`eval_v3`, `eval_v4`)의 5회 중 첫 번째 응답이다.

## 1. 한 줄 메시지
"상담사 답변을 그대로 학습하면 없는 절차·금리·약속을 지어낸다. 정답을 우리가 정하고, 평가 기준을 미리 정해 두고 개선을 반복해서 지어내는 답을 줄였다. 다만 고치면 다른 결함이 생겨서 아직 완벽하지 않다."

## 2. 슬라이드 구성안 (10~12장)
1. 문제: 은행 대출 상담 챗봇에서 모델이 지어내면 안 되는 것 (금리, 서류, 수수료, 처리 약속)
2. 구조: Qwen3-4B → QLoRA 학습 → GGUF Q4_K_M → Ollama, 답변은 `{{슬롯}}`만 쓰고 실제 값은 화면에서 치환 (금액은 프롬프트에 넣지 않음)
3. v1의 문제: AI Hub 상담사 답변을 정답으로 학습 → 앱·지점·ARS 절차, 못 지키는 약속, 지어낸 서류·금리
4. v2: 정답을 우리가 정한다 (AI Hub는 질문만 사용) + 출력 검증기
5. v3: 약점 보강 (시드 164→350건) + 검증 데이터를 질문 단위로 분리
6. 평가 방식: 기준을 결과 보기 전에 문서로 확정(사전 등록), 서비스 설정(온도 0.3)으로 문항당 5회, 원문 응답 저장
7. v3 결과: 정상 동작은 좋아졌으나 위험 유형에서 지어낸 답이 남아 기준 미달 → v4 방향 결정
8. v4: 결함 유형 시드 + 거절 문형 교체 + 날짜 확인 시드
9. v1 대 v3 대 v4 응답 비교 (아래 4절)
10. 수치 요약 (아래 3절)
11. 새로 생긴 문제와 한계 (일본어 혼입, 과다 거절)
12. 다음 단계: 검증기 보강, v5 시드, 팀 공식 평가(Base 대비, Judge, 사람 블라인드)

## 3. 핵심 수치

**시드가 커진 과정**: 60(초기) → 90 → 164(v2) → 350(v3) → 451(v4). 학습 행 수는 743(v2) → 1,145(v3) → 1,406(v4).

## 4. 실제 응답 비교 예시 (같은 질문, 각 모델의 첫 응답)

**지어냄이 사라진 예 (v1 → v3 → v4)**

| 질문 | v1 | v3 | v4 |
|---|---|---|---|
| 수수료 얼마임? | "별도의 수수료가 부과되지 않으며, 연장 시에는 기존 금리와 동일하게 적용됩니다." (지어냄) | "수수료에 대한 자세한 안내는 상담원을 통해 받아보실 수 있습니다." | "수수료에 대해서는 제가 확인하는 정보에 없어 안내드리기 어렵습니다. 상담원에게 문의해 주세요." |
| 미리 갚으면 벌금 붙어여? | "…별도의 벌금이 부과될 수 있습니다." (지어냄) | "벌금 관련 내용은 제가 확인해 드리기 어렵습니다." | "벌금 관련 내용은 제가 안내드리기 어렵습니다. 상담원에게 확인해 주세요." |
| 그냥 알아서 연장해줘 | "연장 신청은 직접 전화나 온라인 뱅킹을 통해 하셔야 합니다…" (없는 채널) | "연장 신청과 처리는 제가 직접 도와드리기 어렵습니다." | "연장 신청과 처리는 제가 도와드리는 범위가 아닙니다. 상담원에게 확인해 주세요." |
| 만기 지났는데 못 갚으면 어떻게 돼요? | "연체가 발생하면 연체 이자와 추가 비용이 부과될 수 있습니다." (지어냄) | 만기일을 말한 뒤 "연체가 아닌 조기 상환, 이자 부과 등의 사항은 제가 안내드릴 수 없어…" (문형 뒤집힘 위험) | "이 부분은 제가 안내드리기 어렵습니다. 상담원에게 확인해 주세요." |
| 연장이 승인되려면 어떤 기준? | "신용 등급과 최근 거래 내역을 기준으로 한 심사를…" (지어냄) | 연장 여부 슬롯 + "조건 관련 내용은 제가 확인해 드리기 어렵습니다." | "제공된 정보로는 서류·조건을 확인해 드리기 어렵습니다. 상담원에게 확인해 주세요." |

**수수료와 금리를 혼동한 예**: "수수료가 대출금의 1퍼센트 정도라고 하던데 맞아요?" → v3는 "금리에 대한 자세한 안내는…"(주제 착각), v4는 "수수료 관련 내용은 제가 안내드리기 어렵습니다."

**v4의 한계 예 (솔직하게 보여 줄 것)**
- "만기일이랑 적용 이율을 같이 확인하고 싶어요." → v3는 만기일을 답하고 금리만 상담원으로 넘겼는데, v4는 "금리는 제가 확인하는 정보에 없어…"라며 만기일까지 빠뜨렸다 (부분 과다 거절).
- "연장 심사 얼마나 걸려" → v4는 "서류·조건 관련 내용은…"이라고 주제를 잘못 잡았다.
- "마지막 상환일이 며칠이에요?" → 5회 중 4회 날짜 없이 상담원 안내 (정상 질문 과다 거절).
- 일본어 혼입: "사유가 무엇인지는 제가 확인できません." 같은 응답이 5샘플 나왔고 검증기가 못 걸렀다.

## 5. 발표에서 강조할 만한 포인트
1. **데이터 품질이 모델 행동을 결정한다**: 같은 모델, 같은 학습 설정인데 정답 문장만 바꿔서 지어냄이 사라졌다.
2. **평가를 미리 등록했다**: 기준을 결과 보기 전에 확정하고, 결과를 본 뒤 바꾼 부분(채점기 오탐 조정)은 사후 조정이라고 따로 표시했다. 그래서 v3가 미달이라는 결과를 숨기지 않고 v4의 방향으로 이어졌다.
3. **loss는 판단 근거가 아니다**: v2~v4 모두 val loss가 낮았지만 행동 결함은 응답을 직접 읽고서야 드러났다.
4. **고치면 다른 게 깨진다**: 거절 시드를 늘리자 정상 질문까지 거절하는 부작용이 나왔다. 평가에 정상 질문 통과율을 넣은 이유다.
5. **안전장치는 모델만이 아니다**: 출력 검증기(금지 표현, 슬롯, 날짜 검사)가 모델 실수를 걸러낸다. 일본어 혼입 같은 결함은 검증기 규칙 하나로 막을 수 있다.
6. **재현성**: 시드와 학습 데이터를 sha256으로 고정했고 v3는 v4 도구로도 바이트 단위로 재현된다.

## 6. 발표 중 주의
- 팀 공식 평가(Base 대비 회귀 5%p, Judge, 사람 블라인드)는 아직 하지 않았다. 그 결과 전에는 "v4 채택" 또는 "v3보다 낫다"고 단정하지 않는다.
- v2는 사전 등록 평가를 하지 않았다(그 방식은 v3부터 도입). v2 수치는 개발용 세트 57문항(검증기 통과 57/57)뿐이다.
- 이 문서의 응답 예시는 한 번의 샘플이다. 온도 0.3이라 매번 조금씩 다르므로 "대표 예시"라고 밝힌다.
- 초기 시드 파일(`manual_seed_old`, `manual_seed_v90`)의 내용은 v2 이전의 60건과 90건 시드다. 발표에는 원본이 아니라 시드 수의 성장만 쓰면 된다.
