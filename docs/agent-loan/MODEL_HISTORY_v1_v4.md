# 대출문의 모델 v1 → v4: 무엇을 고쳤고 결과가 어땠나 (2026-09-30)

모델: Qwen3-4B-Instruct-2507 + QLoRA → GGUF Q4_K_M → Ollama. 학습 파라미터(lr 2e-4, 3 epoch, LoRA r16/alpha32/dropout 0.05, 실효 배치 16, seed 42)는 v2~v4가 같고 **바뀐 것은 학습 데이터(시드)와 거절 문형**이다. 자세한 근거는 `ADR.md`(LN-007, LN-008), 평가 기준은 `EVAL_CRITERIA_v3.md`·`EVAL_CRITERIA_v4.md`, v4 결과는 `EVAL_RESULT_v4.md`에 있다.

## v1 (이전 작업, 기준선)
- AI Hub 71926 상담사 답변을 정답으로 학습했다. 점검한 30건 중 안전한 답이 0건이었고, 우리 서비스에 없는 앱·지점·ARS 절차, 못 지키는 약속, 지어낸 서류·금리를 그대로 말했다.
- 이 모델은 그대로 두었다(`cs-loan-test`, 이후 평가의 기준선).

## v2 — 정답을 우리가 정한다 (LN-007)
**바꾼 것**
- 학습 데이터에서 AI Hub 답변을 쓰지 않는다. AI Hub는 **질문 공급원**으로만 쓰고(`prepare.py --mode replace`), 정답은 수동 시드 164건(×3 복제) + 교체 문장(서류·조건 125건, 금리 126건, 6종 문장 + 마무리 4종)으로 붙였다.
- 출력 검증기 보강(`validate.py`): 없는 채널·못 지키는 약속·서류명을 막는다(LN-004).
- 답변 슬롯 방식: 금액·연장 여부는 `{{principal_remaining}}`, `{{extendable_status}}`, `{{loan_label}}`로만 쓰고 만기일만 숫자로 쓴다.
- 학습 743행 / 검증 133행, 141스텝, 약 25분, eval_loss 약 0.12, 정확도 0.96. 데이터가 쉬워 loss는 판단 근거가 되지 못했다.

**결과** (Golden Set 57문항, 온도 0)
- 검증기 통과 57/57, 서류·금리·수수료 질문에 지어낸 절차·약속이 사라졌다(v1은 새 검증기 기준 약 69%).
- 남은 약점: ① 연장 여부와 원금을 함께 물으면 원금을 빠뜨린 답이 검증기를 통과함(R06), ② 연장 수수료 질문에 "금리"로 답함(F09), ③ 대출 전반을 물으면 아는 정보도 회피함(C28), ④ 답변 문형이 6개로 반복되어 고유 답변 66개·평균 57자로 딱딱함.

## v3 — 약점 보강과 문형 조합 (LN-008)
**바꾼 것**
- 수동 시드 164→**350건**(학습 298 + 질문 단위로 분리한 검증 52). 검증 데이터를 **질문 단위로 나눠** 같은 질문이 학습과 검증에 함께 들어가지 않게 했다.
- 추가한 시드 유형: 연장 여부+원금 복합, 만기·원금·연장 전반 조회, 비용·수수료·위약금 질문(질문의 주제어로 답), 이전 턴을 잇는 맥락 12건, 기본 답변 문형 다양화, 말투 변형 28건(반말·명사형·오타), 마스킹 토큰이 든 질문 16건, 구체 서류명·숫자가 든 질문.
- 학습 1,145행 / 검증 185행, 216스텝, 약 37분(2,222초), 어댑터 기준 eval_loss 0.085.
- 파일 해시를 ADR LN-008에 남기고 이후 덮어쓰지 않기로 했다(v3 재현은 v4 도구로도 바이트 단위로 같다).

**결과**
- 개발 확인(온도 0, 우리가 보며 고치던 세트): Golden Set 57문항 v2 54→v3 57, 새 문항 20건 10→18, 학습에 없던 날짜 10문항 8→10.
- **사전 등록 평가**(`EVAL_CRITERIA_v3.md`, 결과를 보기 전에 기준 확정, 서비스 설정 온도 0.3 ×5, 685샘플): 위험 유형을 겨냥한 새 판정 세트에서 v3가 지어낸 답을 냈다(수동 판정 8건: N14·U03·U10 등, 유형은 처리 요청·조건·수수료·범위 밖·기간). 기준 미달.

## v4 — v3 결함을 겨냥한 시드와 거절 문형 (이번 작업)
**바꾼 것** (기준·해시는 `EVAL_CRITERIA_v4.md`)
- 시드 **451건**(v3 350건에서 중복성 높은 거절 약 30건 정리 + 결함 유형 시드 추가). 학습 1,406행 / 검증 199행, 264스텝, 46분, val loss 0.1394→0.1080→0.1058.
- 추가한 시드: 범위 밖 16, 처리 요청 10, 조건+해당 여부 8, 손해·이득 8, 수수료↔금리 10, 원금+상환액 4, 말투 변형 20, 마스킹 20, 맥락 20, **날짜 확인 10건**(틀린 날짜는 "아니요, 만기일은 X입니다"로 정정 6건, 맞는 날짜는 "네, 맞습니다" 4건).
- **거절 문형 교체**: v3의 "안내드릴 수 있습니다"처럼 모델이 뒤집으면 처리 약속이 되는 "~ㄹ 수 있/없" 문형을 없애고 "~기 어렵습니다", "제가 도와드리는 범위가 아닙니다" 계열로 통일했다(`REFUSAL_TEMPLATES_V4`, v3 상수는 해시로 고정).
- 정상 답변 문구를 자연스러운 문형으로 바꾸고, 시드 해시(451행)를 고정한 뒤에 평가용 새 문항(비교 20, 최종 10)을 썼다. wandb(`cs-loan`/`outputs_v4`)로 학습 곡선을 기록했다.
- 손대지 않은 것(알려진 한계): 연장 불가 정상 답변 끝의 "자세한 사항은 상담원에게 확인해 주세요." 꼬리.

## 세 번의 변경에서 배운 것
1. 데이터의 답변을 바꾸면 모델 행동이 바뀐다(v1→v2 지어냄 제거, v3→v4 뒤집힌 문형 제거). 하지만 거절 시드가 늘면 정상 질문까지 거절하는 부작용이 생긴다(v4의 D10, K06).
2. loss는 판단 근거가 아니다(v2~v4 모두 val loss가 낮았지만 행동 결함은 평가에서 드러났다).
3. 여러 변경을 한 번에 넣어서 어느 변경이 효과를 냈는지 분리하지 못한다(LN-008 트레이드오프).
4. 채점 규칙도 결함이 있을 수 있어서, 사전 등록 결과(strict)와 사후 조정 결과를 항상 따로 표시한다.
5. 현재 상태에서 세 모델의 우열은 단정하지 않는다. v3와 v4는 전체 통과율이 비슷하고 강점·약점이 다르다. 채택은 팀 공식 평가(공용틀, Base 대비 회귀 5%p, Judge, 사람 블라인드)를 보고 정한다.
