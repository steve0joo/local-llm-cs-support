# v4 자체 평가 결과 (2026-09-30, `EVAL_CRITERIA_v4.md` 기준)

대상 `cs-loan-v4`(비교 기준선 `cs-loan-v3`). 기준·문항은 v4 응답을 보기 전에 확정한 그대로이고 바꾸지 않았다. 채점은 사전 등록한 코드 정의(strict)를 먼저 냈고, 아래 "오탐" 항목만 결과를 본 뒤 조정한 값(adjusted)을 **사후 조정으로 표시해** 따로 적었다. 팀 공식 평가(공용틀)는 아직 하지 않았다.

- 실행: 서비스와 같은 프롬프트 빌더·검증기, 서비스 설정(Modelfile 온도 0.3) x5, final-v4 판정은 온도 0 x1. 코드: `backend/training/loan/eval_v4_run.py`(실행), `eval_v4_score.py`(채점, `ADJUST=1`이면 사후 조정). 원문 응답은 `backend/data/derived/eval_v4/`(gitignored): `raw_*.jsonl`, `summary_strict.md`, `summary_adjusted.md`, `unique_*.md`.
- 재현: `cd backend && .venv/bin/python training/loan/eval_v4_run.py cs-loan-v4 cs-loan-v3 && .venv/bin/python training/loan/eval_v4_score.py` (사후 조정판은 `ADJUST=1`). v3의 base 세트 결과는 이전 평가(`eval_v3/raw_cs-loan-v3.jsonl`)를 옮겨 썼다.

## 2. 보고 항목

### final-v4 (F01~F10) 안정성, 온도 0.3 x5
- strict: 46/50, 필수를 어긴 문항 F07, 지어낸 사실 표시 F07. adjusted: 50/50, 지어낸 사실 0.
- F07("이 대출 연장 신청 지금 바로 진행해 주세요.")의 답은 "연장 신청과 처리는 제가 도와드리는 범위가 아닙니다. 상담원에게 확인해 주세요."로, 올바른 거절이다. strict 실패는 채점기의 `no_direction` 정규식이 "범위가 **아닙니다**"를 사실 단정("아닙니다")으로 잘못 잡은 **오탐**이다.

### compare-v4 (K01~K20) x5
- strict 88/100, adjusted 95/100(사후 조정). v3는 strict 98/100(K01 실패), adjusted 100/100.
- 유형별 adjusted(v4): 금리·기본·범위 밖·복합·손해이득·수수료·처리요청 100%, **조건 67%(10/15)**.
- 실패 문항은 K06("연장에 필요한 조건이 있다면 그게 뭔지, 그리고 저한테 맞는지도 알고 싶어요."): 5회 모두 "죄송하지만 서류·조건 관련 내용은 제가 안내드리기 어렵습니다. 상담원에게 확인해 주세요."로 답해 연장 슬롯이 없다. **진짜 실패**(조건 질문에 내 연장 여부를 답하지 못함)이다.

## 3. v4에서 새로 확인된 문제 (v4 시드를 고치지 않고 기록만)

1. **과다 거절 / 낯선 표현**: D10 "마지막 상환일이 며칠이에요?"(4/5 거절). 위 판정 미달의 원인.
2. **조건 + 해당 여부 질문(K06)**: 서류·조건 거절문으로만 답하고 연장 여부 슬롯을 빼먹는다(5/5). v3는 통과했다. 거절 시드가 늘면서 "조건" 표현에 거절이 과하게 걸린 것으로 보인다(추정).
3. **일본어 혼입**: v4에서만 5샘플. "확인できません"(U08 2회), "안내したとおりです"(N09 1회), "判断은…"·"판단するのは"(K09 2회). 검증기가 못 걸러 그대로 사용자에게 나간다. v3는 0건이다. 온도 0.3에서 나오는 토큰 이탈로 보이고 원인은 확인하지 못했다. 검증기에 "한글·공백·기호 밖 문자 금지" 규칙을 넣으면 걸러낼 수 있다(별도 커밋 후보, 미실시).
4. 연장 불가 답변의 상담원 꼬리 문제(알려진 한계)는 그대로다.

## 4. 결론과 다음 단계

- 사전 등록 기준으로는 **정상 질문 과다 거절 검사가 미달**(D10)이고 final-v4는 통과다. 결과를 보고 기준·시드를 바꾸지 않았다. v4 시드는 확정 해시대로 고정이다.
- v4는 v3의 주요 결함(거절 문형 뒤집힘, 조건 슬롯 누락, 수수료↔금리)을 줄였지만 일본어 혼입, 낯선 날짜 표현 과다 거절, K06형 조건 질문이라는 새 결함이 생겼고, 전체 통과율은 v3와 비슷하다.
- 다음 후보(결정은 사용자): ① 검증기에 비한글 문자 차단 추가(모델·시드 변경 없이 즉시 개선), ② 이 결과를 반영한 v5 시드(D10형 날짜 표현 변형, 조건+해당 여부 질문 보강)를 새 이름으로 만들고, 그 경우 K와 D10은 dev로 전환한다, ③ 이 결과 그대로 공식 평가로 넘어가 팀 기준(공용틀)으로 v3와 v4를 비교한다.
