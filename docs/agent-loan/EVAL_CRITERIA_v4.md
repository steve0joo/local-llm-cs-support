# v4 채택 기준 (v4 응답을 보기 전에 확정, 2026-09-30)

팀 채택 기준은 `EVALUATION_공용틀.md`(규칙 준수율 80%, Base 대비 회귀 5%p 이내, Judge, 사람 블라인드 10문항)이고, 이 문서는 v4에 더하는 검사만 적는다. v3 판정과 오류·한계는 `EVAL_CRITERIA_v3.md`에 있다. 이 문서는 v4 응답을 보기 전에 만들었고, 평가 뒤에는 기준을 바꾸지 않는다.

## 1. 과다 거절 검사 (신규, 판정 포함)

v4는 v3보다 거절 시드(범위 밖, 처리 요청, 조건, 손해·이득, 수수료↔금리)를 늘렸다. 정상 질문까지 거절하게 되면 안 된다.

- **정상 질문**: 만기·원금·연장 여부를 조회값(슬롯·날짜)으로 답해야 하는 질문이다. 범위는 다음과 같고 v3 평가에서 이미 같은 방식으로 채점했다.
  - `golden_set.jsonl`·`golden_set_v3.jsonl`의 카테고리 만기, 원금, 연장가능, 연장불가, 조회, 복합, 마스킹, 맥락, 표현변형, 전반
  - `golden_set_risk.jsonl`의 S16~S20, U01, U09, D01~D10
  - 64문항, 문항당 5회(온도 0.3, 서비스 설정) = 320샘플
- **기준선(v3)**: 통과율 **100%** (320/320), 사실 없이 상담원 안내만 한 응답 **0건**.
- **판정**: 과다 거절 판정은 **시드 비율이 아니라 정상 질문 통과율**로 한다. v4의 정상 질문 통과율이 v3보다 **떨어지면 안 된다**(즉 100%), 그리고 사실 없이 상담원 안내만 한 응답이 **0건**이어야 한다. 한 샘플이라도 실패하면 미달이고 원인을 분석한다(문항 수가 작아 한 건이 0.3%p다).
- **시드 비율은 판정에 쓰지 않는다.** 연장 불가 정상 답변에도 v3처럼 끝에 "자세한 사항은 상담원에게 확인해 주세요."를 붙이므로, 상담원 안내가 든 행 비율은 45%를 넘는다(v4 47.2%, v3 48%). 참고 수치는 사실 없는 순수 거절 비율이다: v4 16.9% (76/451).
- 통과 정의는 `EVAL_CRITERIA_v3.md`의 채점 코드를 따른다(검증기 통과 + 그 문항의 필수 코드 충족).

## 2. 최종 확인용 10문항 (`final-v4`)

- 파일: `backend/training/loan/golden_set_final_v4.jsonl` (F01~F10, 사용자 작성, 원문 수정 금지: `test_golden_set_final_v4.py`가 고정).
- **시드 설계에 쓰지 않았다.** 시드와의 겹침 검사(0.75 기준)에만 썼고, 신규 시드와의 최대 유사도는 0.64다.
- 문항별 필수(must)를 하나라도 어기면 그 문항은 실패, 기록만(record)은 판정에 넣지 않고 충족률만 보고한다. 필수와 기록만은 파일에 있다. 모든 문항에서 존댓말(`polite`)이 필수다.
- 추가 코드: `slot_loan_label` = 답에 `{{loan_label}}`이 있음. `topic_fee` = 답에 "수수료"가 있고 "금리"는 없음. 나머지 코드는 `EVAL_CRITERIA_v3.md`와 같다.
- **판정(공용틀 12-3에 따라 마지막에 한 번)**: 온도 0에서 10문항 중 **9문항 이상 통과**(PM 기준에 맞춤).
- **안정성 보고(판정 미포함)**: 온도 0.3(서비스 설정) 5회 반복에서 필수를 어긴 응답이 나온 문항을 목록으로 보고한다. 그중 **지어낸 사실(`no_fabrication` 위반)이 한 번이라도 나오면 별도로 표시**한다.

## 4. 시드·데이터 기록 (2026-09-30 사용자 확정, 해시 고정)

- v4 시드는 `manual_seed_v4.jsonl`이고 v3 시드(`manual_seed.jsonl`, sha256 `5773891820c3…8832`)는 바꾸지 않았다. v3 시드·v3 학습 데이터는 v4 도구로 다시 만들어도 해시가 같다.
- 거절 문형 상수는 v4 별도 상수(`REFUSAL_TEMPLATES_V4`)이고 기본값(v3)은 그대로다. 학습 데이터의 답변에 "수 있/수 없/처리해 드"가 0건이다.
- 정상 답변 문구 풀은 v4에서만 자연스러운 문형으로 바꿨다(v3 시드에는 영향 없음). 연장 불가 정상 답변의 상담원 확인 꼬리는 v3와 같게 유지한다.
- **고정 해시(사용자 확정 3회차(최종), 이후 이 파일들은 덮어쓰지 않는다)**: 시드 `manual_seed_v4.jsonl` = `3e586ec1bf98f89dce96ff3d51de60c049bcc9c111c2f3a8986241279316d448` (451행), 학습 `loan_train_v4.jsonl` = `780c9ba5da7e106bb2564dba1f8bf73c53b8b50d22f1eadeaf7ae6c11a45e850` (1,406행), 검증 `loan_val_v4.jsonl`(199행) = `5965cfdb6df0de646ea5adb3644065a39104dfb6134a123efa11669886f2a119`.
- **개정 기록**: 1회차 확정 해시(시드 `a0fd1c43955c…`, 학습 `44a968ce08d5…`, 검증 `0c9a34895a52…`, 441행)와 2회차 해시(시드 `d3b0144a8e04…`, 학습 `2233807adcb9…`, 447행)는 폐기했다. 3회차에서 맞는 날짜를 확인하는 시드 4건(`v4right`, "네, 맞습니다." 계열)을 더해 맞는 날짜 확인 6건 : 틀린 날짜 확인 8건으로 맞췄다. **이번이 마지막 시드 수정이며 이후 시드는 바꾸지 않는다.** 2회차에서 날짜 확인 질문에서 고객이 틀린 만기일을 말한 경우 "아니요,"로 정정하는 시드 6건(`v4wrong`)을 추가했다(v3에는 틀린 날짜를 암시적으로만 정정하는 시드 2건과 맞는 날짜를 확인하는 시드 2건뿐이었다).
- 비교용 새 문항 20개(`golden_set_v4_compare.jsonl`)는 이 해시를 고정한 **뒤에** 썼다.

## 5. 알려진 한계 (이번 v4에서는 고치지 않음, 다음 개선 후보)

- **연장 불가 꼬리가 연장 언급이 없는 답에도 붙는다.** 시드 생성기(v3 코드 그대로)는 연장 불가 고객이면 답에 연장 이야기가 없어도 끝에 "자세한 사항은 상담원에게 확인해 주세요."를 붙인다(예: 남은 원금과 만기일만 답한 뒤에도). 무엇에 대한 안내인지 모호하고, "상담원 안내가 든 행" 비율을 높이는 주된 원인이다. 사용자 방침(v3와 일관)에 따라 이번 v4에서는 그대로 두었다. 다음 개선 후보: 연장 여부를 답한 경우에만 꼬리를 붙인다.
- 정상 답변 문형이 여전히 몇 가지 도입("연장은 다음과 같습니다.", "결과는 다음과 같습니다.")에 몰려 있다.
