# PRD: 프론트엔드 (챗봇 UI)

- 담당: 나 · 브랜치: `feat-frontend`
- 먼저 읽을 문서: `docs/PRD.md`, `docs/ARCHITECTURE.md`(계약 1, 계약 4의 슬롯 형식, 계약 6의 데모 고객 ID, 코드·테스트 규칙), `docs/frontend/UI_GUIDE.md`

## 목표
고객이 메시지 한 번으로 상담을 시작하고, 선택지 버튼으로 적은 단계 안에 업무를 끝내는 챗봇 화면을 만든다.

## 사용자 스토리
1. 고객은 입력창에 문의를 보내고 봇 답변을 대화 형태로 본다.
2. 고객은 잔액을 물으면 실제 금액이 채워진 문장을 본다. 화면이 `text`의 `{{슬롯}}`을 `slots` 값으로 치환한다.
3. 고객은 되묻기(type=clarify)나 계좌 선택처럼 선택지가 있으면 버튼을 눌러 바로 답한다. 다시 타이핑하지 않아도 된다.
4. 고객은 미지원 주제(type=unsupported)에서 안내 문구와 "상담원 연결" 안내를 본다.
5. PM은 화면 상단에서 데모 고객(`C001`~`C003`)을 바꿔 가며 시나리오를 시험한다.

## 기능 범위
- 대화 목록(고객 말풍선 / 봇 말풍선), 입력창, 전송 버튼(Enter 전송). 앞뒤 공백을 뺀 입력이 비어 있으면 보내지 않는다
- 대화가 비었을 때(첫 화면·고객 변경 직후) 대화 영역에 안내 문구를 보여준다. 말풍선이 아니다
- 응답을 기다리는 동안 입력 중 표시. 입력창·전송 버튼·선택지·고객 선택을 비활성화한다
- 슬롯 치환: `text`의 `{{name}}`을 `slots`의 값으로 바꾼다. 값이 없으면 "확인할 수 없습니다"로 표시한다(판정 기준은 `docs/frontend/ARCHITECTURE.md` "fillSlots 규칙"). `text`와 슬롯 값의 줄바꿈은 그대로 보인다
- 선택지 버튼: 클릭하면 `{message: label, choice}`를 보낸다
- 데모 고객 선택 드롭다운. 바꾸면 새 `session_id`로 대화를 초기화한다
- 오류(네트워크 오류·2xx가 아닌 응답) 시 "잠시 후 다시 시도해 주세요" 봇 메시지를 오류 색으로 보여준다
- 세부 동작은 `docs/frontend/ARCHITECTURE.md` "화면 동작 규칙"을 따른다

## 인수 기준
- 슬롯 치환 함수의 단위 테스트가 통과한다(치환 성공, 누락 슬롯, 슬롯 없는 문장).
- `lib/api`를 목으로 바꾼 `page` 테스트에서 잔액 응답을 받으면 화면에 `1,234,567원` 형식의 금액이 보이고 `{{`가 남지 않는다. 실제 백엔드로 보는 확인은 `docs/frontend/ARCHITECTURE.md` "통합 후 확인"에서 한다.
- clarify 응답의 선택지를 클릭하면 `choice`가 담긴 요청이 나가고, 직접 입력한 요청에는 `choice` 키가 없다(테스트로 확인).
- 고객을 바꾸면 대화가 비고 다음 요청의 `session_id`가 바뀐다(테스트로 확인).
- `npm run lint && npm run build && npm run test`가 통과한다.

## 제외
- 로그인, 대화 저장, 다중 세션 목록, 스트리밍 표시, 다크모드 전환, 별도 잔액 카드/표, 모바일 앱

## 의존성 / 확인 필요
- 백엔드 `/api/chat`은 팀원C가 먼저 스텁으로 머지한다. 그 전에는 테스트에서만 `lib/api`(또는 `fetch`)를 목(mock)으로 바꿔 개발한다. 런타임 목 모드는 두지 않는다(`docs/frontend/ADR.md` FE-005).
- 백엔드 없이 개발 서버를 띄우면 요청이 실패해 오류 말풍선이 보인다. 그 상태로 화면 모양과 오류 경로를 확인할 수 있다.
- "상담원 연결"은 실제 연결 없이 안내 문구만 보여준다.
