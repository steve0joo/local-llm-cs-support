# PRD: 프론트엔드 (랜딩 + 챗봇 UI)

- 담당: 나 · 브랜치: `feat-frontend`
- 먼저 읽을 문서: `docs/PRD.md`, `docs/ARCHITECTURE.md`(계약 1, 계약 4의 슬롯 형식, 계약 6의 데모 고객 ID, 코드·테스트 규칙), `docs/frontend/UI_GUIDE.md`

## 목표
한 페이지에서 두 가지를 한다.
1. 랜딩: 스크롤하면 미니어처 장면 4개를 지나며 "은행 상담 데이터로 학습한 로컬 AI가 문의를 나눠 받고, 개인정보는 모델 앞에서 가린다"를 보여준다.
2. 챗: 페이지 맨 끝(`#chat`)에서 데모 고객으로 직접 물어본다. 메시지 한 번으로 상담을 시작하고, 선택지 버튼으로 적은 단계 안에 업무를 끝낸다.

## 사용자
- 쇼케이스 방문자(발표 심사위원·외부인): 스크롤로 동작 원리를 보고 마지막에 체험한다. 조작은 발표자 PC에서 한다(`docs/frontend/ARCHITECTURE.md` "시연 방식").
- PM: 데모 고객을 바꿔 가며 인수 시나리오를 시험한다.

## 사용자 스토리
1. 방문자는 스크롤로 장면 01~04를 지나며 문제 → 학습 → 라우팅 → 개인정보 보호 순서로 설명을 본다.
2. 방문자는 어느 장면에서든 상단바 "직접 물어보기"로, 04 장면에서는 CTA로 챗에 바로 간다.
3. 방문자는 대화가 비어 있을 때 예시 질문 칩을 눌러 바로 보낸다. 무엇을 물을지 몰라 막히지 않는다.
4. 고객은 입력창에 문의를 보내고 봇 답변을 대화 형태로 본다.
5. 고객은 잔액을 물으면 실제 금액이 채워진 문장을 본다. 화면이 `text`의 `{{슬롯}}`을 `slots` 값으로 치환한다.
6. 고객은 되묻기(type=clarify)나 계좌 선택처럼 선택지가 있으면 버튼을 눌러 바로 답한다. 다시 타이핑하지 않아도 된다.
7. 고객은 미지원 주제(type=unsupported)에서 안내 문구와 "상담원 연결" 안내를 본다.
8. 방문자는 오류가 났거나 다른 시나리오를 해 보고 싶으면 "새 대화"로 같은 고객의 대화를 처음부터 시작한다.
9. PM은 챗 패널 상단에서 데모 고객(`C001`~`C003`)을 바꿔 가며 시나리오를 시험한다.

### 챗 섹션 (`#chat`)
- 섹션 카피: eyebrow "직접 체험", 제목 "데모 고객으로 물어보세요.", 본문 "가상 고객 데이터입니다. 실제 개인정보는 입력하지 마세요."
- 챗 패널 상단: 데모 고객 선택 드롭다운 + "새 대화" 버튼. 고객을 바꾸거나 "새 대화"를 누르면 새 `session_id`로 대화를 초기화한다("새 대화"는 고객을 유지한다)
- 대화 목록(고객 말풍선 / 봇 말풍선), 입력창, 전송 버튼(Enter 전송). 앞뒤 공백을 뺀 입력이 비어 있으면 보내지 않는다
- 대화가 비었을 때(첫 화면·초기화 직후) 대화 영역에 안내 문구를 보여준다. 말풍선이 아니다
- 대화가 비었을 때 입력창 위에 예시 질문 칩을 보여준다. 누르면 직접 입력한 것과 똑같이 보낸다(`choice` 없음)
- 응답을 기다리는 동안 입력 중 표시. 입력창·전송 버튼·선택지·예시 칩·고객 선택·"새 대화"를 비활성화한다
- 슬롯 치환: `text`의 `{{name}}`을 `slots`의 값으로 바꾼다. 값이 없으면 "확인할 수 없습니다"로 표시한다(판정 기준은 `docs/frontend/ARCHITECTURE.md` "fillSlots 규칙"). `text`와 슬롯 값의 줄바꿈은 그대로 보인다
- 선택지 버튼: 클릭하면 `{message: label, choice}`를 보낸다
- 오류(네트워크 오류·2xx가 아닌 응답·형식이 어긋난 응답) 시 "잠시 후 다시 시도해 주세요" 봇 메시지를 오류 색으로 보여준다
- 세부 동작은 `docs/frontend/ARCHITECTURE.md` "화면 동작 규칙"을 따른다

### 예시 질문 칩
| 문구 | 기대 동작 |
|------|----------|
| 잔액 얼마 남았어요? | 잔액조회 (C001 금액 표시, C002 계좌 선택) |
| 대출 만기가 언제예요? | 대출문의 |
| 연체 이자가 얼마예요? | 이자/연체 |
| 대출 잔액이랑 이자 얼마 남았어요? | 복합 문의 되묻기 |
| 환전하고 싶어요 | 미지원 안내 + 상담원 연결 안내 |

발표 전에 실제로 동작하지 않는 칩(에이전트가 아직 스텁이라 "준비 중인 기능입니다."로 답하는 칩)은 뺀다(`docs/frontend/ARCHITECTURE.md` "발표 전 체크리스트").

## 인수 기준
- 슬롯 치환 함수의 단위 테스트가 통과한다(치환 성공, 누락 슬롯, 슬롯 없는 문장).
- `lib/api`를 목으로 바꾼 `page` 테스트에서 잔액 응답을 받으면 화면에 `1,234,567원` 형식의 금액이 보이고 `{{`가 남지 않는다. 실제 백엔드로 보는 확인은 `docs/frontend/ARCHITECTURE.md` "통합 후 확인"에서 한다.
- clarify 응답의 선택지를 클릭하면 `choice`가 담긴 요청이 나가고, 직접 입력한 요청에는 `choice` 키가 없다(테스트로 확인).
- 고객을 바꾸면 대화가 비고 다음 요청의 `session_id`가 바뀐다(테스트로 확인).
- 예시 칩은 빈 대화에서만 보이고, 누르면 `choice` 키가 없는 요청이 한 번 나간다. 더블클릭해도 한 번이다(테스트로 확인).
- "새 대화"를 누르면 대화가 비고 칩이 다시 보이며, 다음 요청은 같은 `customer_id`와 새 `session_id`로 나간다(테스트로 확인).
- 응답의 `text`가 문자열이 아니거나 `options`가 배열이 아니면(없거나 `null`은 허용) 오류 말풍선이 보이고 페이지가 깨지지 않는다(테스트로 확인).
- 스크롤 월드 엔진은 준비 이벤트가 여러 번 와도 같은 컨테이너에 한 번만 마운트되고, 로드 실패·함수 없음·마운트 예외면 랜딩 컨테이너를 숨긴다(테스트로 확인).
- `npm run lint && npm run build && npm run test`가 통과한다.
- 브라우저 확인(`phases/frontend/step17.md` landing-manual-check)을 통과한다.

## 제외
- 로그인, 대화 저장, 다중 세션 목록, 스트리밍 표시, 다크모드 전환, 별도 잔액 카드/표, 모바일 앱
- 새 영상·이미지 생성, 장면 사이 연결(connector) 클립, 모바일 전용 세로 영상. 에셋은 웹사이트에서 가져온 것만 쓴다
- 문의 폼·메일 링크(웹사이트의 "도입 문의"는 없앤다)
- 데모 고객 설명 표시, 고객별로 다른 예시 칩
- 방문자 기기 접속(LAN·HTTPS), CSP 등 보안 헤더, 입력 길이 제한(게이트웨이 몫)
- 엔진 로드 재시도·로딩 표시·오류 문구, 응답 항목 단위 검증(선택지 `label` 타입 등)

## 의존성 / 확인 필요
- 백엔드 `/api/chat`은 팀원C가 먼저 스텁으로 머지한다. 그 전에는 테스트에서만 `lib/api`(또는 `fetch`)를 목(mock)으로 바꿔 개발한다. 런타임 목 모드는 두지 않는다(`docs/frontend/ADR.md` FE-005).
- 백엔드 없이 개발 서버를 띄우면 요청이 실패해 오류 말풍선이 보인다. 그 상태로 화면 모양과 오류 경로를 확인할 수 있다.
- "상담원 연결"은 실제 연결 없이 안내 문구만 보여준다.
- 예시 칩 목록과 04 장면 카피는 발표 시점의 실제 동작에 맞춘다. 대출·이자 에이전트, 마스킹·슬롯(인수 기준 5·6)이 준비됐는지 발표 전에 확인한다.
