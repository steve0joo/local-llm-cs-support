# ADR: 프론트엔드

> 공통 결정(ADR-001~008)은 `docs/ADR.md`를 따른다. 여기에는 프론트 영역 결정만 적는다.

### FE-001: 슬롯 치환은 프론트의 순수 함수로 한다
**결정**: 백엔드는 `text`(`{{슬롯}}` 포함)와 `slots`를 따로 보낸다. 프론트 `lib/fillSlots.ts`가 렌더링 시점에 치환한다.
**이유**: PRD의 "실제 값은 최종 화면에서만 치환"을 그대로 구현한다. 순수 함수라 테스트가 쉽다.
**트레이드오프**: 치환이 누락되면 화면에 `{{balance}}`가 노출될 수 있다. 누락 슬롯은 "확인할 수 없습니다"로 대체하고 테스트로 막는다.

### FE-002: 상태는 useState만 사용
**결정**: 전역 상태 라이브러리(Redux, Zustand 등)와 데이터 페칭 라이브러리(SWR, React Query)를 쓰지 않는다.
**이유**: 화면 하나, 요청 하나(`POST /api/chat`)뿐이다.
**트레이드오프**: 화면이 늘어나면 다시 검토한다.

### FE-003: 데모 고객 선택으로 본인 인증을 대신한다
**결정**: 상단 드롭다운에서 `C001`~`C003`을 고르면 그 고객으로 대화한다.
**이유**: 실제 인증은 MVP 범위 밖이다. PM이 계좌 선택·연체 같은 시나리오를 빠르게 바꿔 볼 수 있다.
**트레이드오프**: 인증 흐름의 턴 수는 인수에서 검증하지 않는다.

### FE-004: 테스트는 Vitest + Testing Library
**결정**: `fillSlots`, `sendChat` 요청 형태, 선택지 클릭 동작을 Vitest와 React Testing Library로 테스트한다.
**이유**: Next.js + TS 조합에서 설정이 가장 가볍다. Harness TDD 훅(테스트 파일 선작성)과 맞는다.
**트레이드오프**: E2E 테스트는 하지 않는다. 통합 확인은 PM 인수 시나리오로 한다.

### FE-005: 목(mock)은 테스트에서만 쓴다
**결정**: `lib/api`와 `fetch`는 Vitest 테스트에서만 목으로 바꾼다. 환경변수로 가짜 응답을 돌려주는 런타임 목 모드나 별도 mock 서버는 만들지 않는다. PRD의 잔액 화면 인수 기준은 `sendChat`을 목으로 바꾼 `page` 테스트로 확인한다.
**이유**: 목 코드가 제품 코드에 섞이지 않는다. 화면 규칙(슬롯 치환·선택지·오류)은 테스트가 결정적으로 확인한다.
**트레이드오프**: 실제 응답을 브라우저에서 보는 확인은 백엔드와 모델이 준비된 뒤로 미뤄진다(ARCHITECTURE "통합 후 확인"). 그 전의 브라우저 확인은 화면 모양과 오류 경로까지만 한다.

### FE-006: 프론트 요청 타임아웃은 두지 않고, rewrites 프록시 제한을 120초로 늘린다
**결정**: `sendChat`에 타임아웃·재시도를 넣지 않는다. `next.config.ts`의 `experimental.proxyTimeout`을 120초로 둔다. 값을 주지 않으면 Next 16 rewrites 프록시는 30초에 끊는다.
**이유**: 모델을 처음 올리는 요청은 10초 목표보다 오래 걸릴 수 있다. 앞단에서 먼저 끊으면 화면은 오류인데 백엔드 세션에는 그 턴이 기록되는 엇갈림이 생긴다.
**트레이드오프**: 백엔드가 멈추면 최대 120초 동안 입력 중 표시가 이어진다. 응답 시간 인수 기준(10초)은 벤치마크로 따로 본다.

### FE-007: 선택지 활성 판정에서 오류 말풍선은 건너뛴다
**결정**: 선택지는 가장 최근의 오류가 아닌 봇 메시지의 것만 누를 수 있다.
**이유**: 선택지 요청이 실패해도 같은 버튼을 다시 눌러 재시도할 수 있다. 계좌 선택처럼 `choice`가 필요한 요청은 직접 입력으로 대신할 수 없다.
**트레이드오프**: 백엔드가 요청을 처리한 뒤 응답만 실패한 경우, 재시도하면 같은 선택이 두 번 처리될 수 있다. 데모 규모에서는 받아들인다.

### FE-008: 스크롤 월드 엔진 원본을 public에 두고 수정하지 않는다
**결정**: 웹사이트(`~/Projects/local-llm-cs-support-website/`)의 `scrub-engine.js`(바닐라 JS, 의존성 0)와 에셋을 `frontend/public/scroll-world/`에 바이트 그대로 복사한다. `ScrollWorld`가 `next/script`로 불러 `onReady`에서 `window.mountScrollWorld`로 마운트한다. 엔진은 수정·번들링·lint하지 않고, 테마와 레이아웃은 `globals.css`의 레이어 밖 CSS로만 바꾼다.
**이유**: 스크롤→영상 시간 매핑, Blob 로딩, 크로스페이드, 모바일 하드닝(seek 합치기, iOS priming)이 이미 검증돼 있다. 원본과 같아야 나중에 교체·비교가 쉽다. 같은 origin 파일이라 CDN에서 JS를 받지 않는다.
**트레이드오프**: 엔진에 정리(destroy) 함수가 없다. 컨테이너가 비었을 때만 마운트해서 중복 DOM은 막지만, dev에서 다시 마운트되면 이전 인스턴스의 `window` 리스너와 rAF 루프가 남는다(개발 중에만). 페이지가 하나라 프로덕션에서는 문제없다. 라우트를 늘려 랜딩이 언마운트될 수 있게 되면 다시 검토한다. 엔진 CSS는 `@layer sw`로 Tailwind 레이어보다 뒤에 선언돼서, 엔진 요소를 Tailwind 클래스로는 덮어쓸 수 없다.

### FE-009: 챗은 엔진 밖의 일반 섹션으로 둔다
**결정**: 챗은 엔진 섹션이 아니라 엔진 컨테이너 뒤의 `<section id="chat">`이다. 엔진의 고정 레이어는 `relative z-[45]`와 불투명 배경으로 덮는다. 엔진이 실패하면 랜딩 컨테이너를 숨겨 챗 섹션이 첫 화면이 된다. 상단바 CTA와 04 CTA는 `#chat` 앵커다.
**이유**: 엔진 섹션은 장면(이미지·영상)과 카피만 그리고, 상태를 가진 React 컴포넌트를 넣을 자리가 없다. 챗을 엔진과 떼어 두면 엔진이 실패해도 핵심 체험인 챗은 남는다.
**트레이드오프**: 04 장면 카피가 고정된 채 남아 있어서 z-index로 덮어야 한다. 엔진 nav에 "체험" 항목을 넣을 수 없어서 상단바 CTA로 대신한다. 챗 섹션에 있는 동안 nav 활성 표시는 04에 머문다.
