# PRD: 로컬 LLM 은행 상담 보조 AI (MVP)

> 이 문서는 팀 공통 요약본이며, 영역별 세부 요구사항은 `docs/<영역>/PRD.md`에 있다.

## 목표
고객이 상담 채팅을 한 번 보내면 주제를 분류해 전문 에이전트로 연결하고, 개인정보를 모델에 노출하지 않으면서 기존 챗봇보다 전문적이고 적은 단계로 업무를 끝내게 한다.

## 사용자
- 은행 고객 (챗봇 사용자)
- PM (인수 담당 — 고정 시나리오로 직접 합격/불합격 판정)

## 핵심 기능
1. 챗봇 UI에서 고객 메시지를 받아 9개 상담 주제 중 하나로 분류한다.
2. 지원 주제 3개는 각 전문 에이전트가 답한다.
   - 거래내역/잔액조회 → 잔액조회 에이전트
   - 대출문의(만기/연장/조회 등) → 대출문의 에이전트
   - 이자/연체금액 → 이자/연체 에이전트
3. 나머지 6개 주제는 "해당 주제는 아직 지원하지 않습니다" 안내 후 상담원 연결을 안내한다.
4. 두 주제에 걸친 문의(예: "대출 잔액이랑 이자 얼마 남았어요?")는 한쪽으로 보내지 않고 "어느 쪽을 먼저 도와드릴까요?"라고 되묻는다.
5. 주민등록번호·카드번호·계좌번호·전화번호·주소·금액은 모델에 도달하기 전에 마스킹한다.
6. 에이전트는 mock API로 고객 데이터를 조회한다. 모델은 `{{슬롯}}` 자리표시자만 쓰고, 실제 값은 화면에서만 치환한다.
7. 라우터와 에이전트 3개는 모두 오픈 모델(Qwen 계열)을 QLoRA로 파인튜닝한 로컬 양자화 모델이다.

## 인수 기준 (PM이 직접 판정)
| # | 기준 |
|---|------|
| 1 | 라우팅: PM 고정 테스트 문의가 올바른 에이전트 또는 미지원 안내로 간 비율 90% 이상 |
| 2 | 복합 문의: 두 주제에 걸친 문의는 되묻기. 한쪽으로만 보내면 불합격 |
| 3 | 답변 품질: 에이전트당 고정 질문 10건(총 30건) 중 27건 이상 통과. 통과 = ① 주제 적합 ② 사실을 지어내지 않음(모르면 상담원 연결 안내) ③ 존댓말 상담 톤 |
| 4 | 사실 생성: 데이터에 없는 금리 수치·실제 상품명·없는 서류 요건을 지어내면 1건이라도 즉시 불합격 |
| 5 | 마스킹: 고정 시나리오 입력 후 모델 입력 로그에 필수 마스킹 항목 원본 값이 0건 |
| 6 | 잔액 화면: 모델은 "현재 잔액은 {{balance}}입니다"를 생성하고, 화면에는 실제 금액(예: 1,234,567원)이 표시됨 |
| 7 | 응답 시간: 메시지 전송 후 첫 응답까지 10초 이내 (Windows·Mac 모두) |
| 8 | 실행 환경: Windows RTX 4060 노트북과 macOS(M4 Pro 24GB) 양쪽에서 모델 추론까지 로컬로 데모 동작 |

## MVP 제외 사항
- 나머지 6개 주제의 전문 에이전트, 범용 폴백 에이전트, 가까운 에이전트로 강제 라우팅
- 실제 은행 시스템 연동, 실제 본인 인증 (데모 고객을 UI에서 선택하는 것으로 대체)
- 실제 상담원 연결 (안내 문구만 표시)
- 자동 유사도 평가, 파인튜닝 전 모델과의 A/B 비교
- 별도 잔액 카드/표 UI
- Windows가 모델을 서빙하고 Mac은 UI만 띄우는 원격 구성
- 스트리밍 응답, 로그인·회원 관리, 배포 인프라

## 제약
- 데이터: AI Hub 71926 금융분야 고객상담 데이터 중 은행(하나은행) 부분만 사용한다. 데이터와 가공본, 모델 가중치는 git에 올리지 않는다(제3자 제공 금지). 국외 클라우드 학습도 하지 않는다.
- 학습 장비: 공용 Windows 노트북 1대(i7-13620H, RAM 32GB, RTX 4060 Laptop 8GB VRAM)에서 팀원이 순서대로 학습한다.
- 데모 장비: 위 Windows 노트북과 Mac M4 Pro 24GB.

## 디자인
- 매일 쓰는 은행 상담 도구처럼 차분하고 읽기 쉽게 만든다. 세부 규칙은 `docs/frontend/UI_GUIDE.md`를 따른다.

## 확정된 설계 결정 (2026-09-28)
- 에이전트 답변 생성: 파인튜닝 + 학습 데이터 정제로 확정한다. RAG는 쓰지 않는다. 모범답변에 섞인 지어낸 값은 정제로 걸러내고, 시간에 따라 바뀌는 정보(금리·상품)는 답하지 않고 상담원 확인을 안내한다(`docs/ADR.md` ADR-005).
- 복합 문의 판별: 라우터 모델은 주제 1개만 출력하고, `router.classify()`의 키워드 규칙이 지원 주제 2개 이상을 감지하면 되묻는다(`docs/router/ADR.md` RT-002).

## 확인 필요 (전체 공통)
아래 4건은 코드 착수를 막지 않는다. 모델이 준비되기 전에는 `llm.generate`를 목(mock)으로 바꿔 TDD로 진행한다. 각 항목은 담당이 게이트 시점까지 확정한다.

- 베이스 모델 크기 — **담당**: 팀원C 벤치마크 후 팀 확정 · **게이트**: 에이전트 학습 착수 전. 한 요청(라우터 → 에이전트)의 첫 응답이 10초 안에 오는 크기를 벤치마크로 정한다(`docs/ADR.md` ADR-005).
- 턴 상한 — **담당**: PM · **게이트**: 인수 전. 시드는 "세 주제에 같은 기준, 3턴 이상 허용"까지만 정했고 숫자는 정하지 않았다. 현재 설계에서 가장 긴 경우는 봇 응답 3회(복합 되묻기 → 계좌 선택 → 답변)다.
- PM 고정 시나리오 셋 — **담당**: PM · **게이트**: 인수 전. 인수 기준 1~6을 모두 이 셋으로 판정하지만 아직 없다. 라우팅 문항(주제별 수·복합 문의 포함)과 에이전트별 10문항을 PM이 작성한다.
