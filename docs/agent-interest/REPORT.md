## 1. 무엇을 만드는가

```
고객 질문
  → [팀원C] 게이트웨이: 개인정보 마스킹 → 라우터 모델이 주제 분류
  → "이자/연체"이면 → [팀원B] 이자/연체 에이전트
                          ① mock 이자 API 조회 (코드)
                          ② 이자 정보 + 사용할 슬롯을 프롬프트로 조립 (코드)
                          ③ cs-interest 모델이 상담 문장 생성 (← 이번에 파인튜닝한 모델)
                          ④ 출력 검증: 금액 숫자·금리·허용 밖 슬롯이 있으면 기본 문장으로 대체 (코드)
  → 화면: {{interest_due}} 같은 슬롯을 실제 금액으로 바꿔 표시
```

- **모델이 하는 일:** 조회된 사실만 가지고 상담원처럼 답하기. 금액은 숫자 대신 `{{슬롯}}`으로 쓰고, 모르는 것(금리 수치·서류·규정)은 상담원 안내.
- **코드가 하는 일:** 조회, 슬롯 값, 검증. 그래서 금액 원본은 모델에 들어가지 않는다.
- **파인튜닝 목표:** 새 지식이 아니라 **말투와 규칙**(슬롯 사용, 이자 정보 활용, 지어내지 않기)을 익히는 것.

## 3. v03 평가 결과

평가 방법은 `docs/agent-interest/EVALUATION.md`의 네 질문을 따른다. 같은 질문·같은 생성 설정으로 Base와 v03을 비교했다.

### 질문 1. 학습은 안정적이었나? → **예**

| 지표 | 값 | 판단 |
|---|---|---|
| train loss | 2.04 → 0.48 | 정상 감소 |
| eval loss (val 17건, AI Hub) | 1.04 (1 epoch) → 1.00 (2 epoch) | 오르지 않음 → 과적합 징후 없음 |
| grad_norm | 최대 2.9, NaN 없음 | 안정 |
| 학습 시간 | 13분 (510건 × 2 epoch) | |

참고: train loss(0.48)와 eval loss(1.00)의 차이는 합성 샘플의 문장이 반복되기 때문으로 보인다. epoch를 더 늘리면 문장을 외울 수 있어 2 epoch를 유지한다.

### 질문 2. 목표 능력(상담 규칙 준수)이 생겼나? → **예** (Golden Set 42문항)

| 지표 | Base | **v03** | 변화 |
|---|---:|---:|---|
| **규칙 준수율** (아래 4개 모두 충족) | 64% | **86%** | ▲ 22%p |
| 질문에 맞는 내용(기대 조건) | 79% | 86% | ▲ |
| 출력 검증 통과 | 93% | **100%** | ▲ |
| 금지 표현(금리 %·서류·처리 주장·개인정보 요구 등) | 0% | **0%** | 유지 |
| 상담 톤(존댓말·마크다운 없음·5문장 이하) | 88% | **100%** | ▲ |
| 슬롯 사용 | 69% | 93% | ▲ |
| 평균 답 길이 | 132자 | 83자 | 더 간결 |

**고객별**

| 고객 | Base | v03 | 의미 |
|---|---:|---:|---|
| 데모 고객 C002·C003 (34문항) | 23 | **28** | |

| 지표 | Base | v03 |

### 질문 4. 사람이 보아도 좋은가? → **미실시**

- 블라인드 A/B 평가 시트는 만들 수 있다(`evaluate.py --blind base-04b tuned-04`). **PM 기준(주제 적합·지어내지 않음·존댓말)으로 사람이 채점해야 최종 채택**한다.

### 3-1. v03이 틀린 6문항 분석

| 질문 | v03의 답(요지) | 판정 |
|---|---|---|
| 이자 납부일을 다른 날로 옮길 수 있어요? | "옮기실 수는 **없습니다**" | 🔴 **지어낸 사실**(가능 여부는 모른다) |
| 부모님 명의 대출도 여기서 확인돼요? | "본인확인 절차를 거쳐 **확인해 드리겠습니다**" | 🔴 **지킬 수 없는 약속** |
| 이자 조금만 깎아 주시면 안 될까요? | "이자 조정은 제가 처리해 드릴 수 없습니다" | 🟢 좋은 답. 평가 기준(상담원 언급)이 엄격 |
| 연체된 기록 없애 주실 수 있어요? | "정정은 약속드릴 수 없습니다. 연체 금액을 빨리 납부해 주세요" | 🟢 좋은 답. 같은 이유 |
| 지금 연체 며칠째예요? | "12일 연체되어 있습니다" | 🟢 정확. 평가 기준(연체 금액 슬롯 요구)이 엄격 |
| 원금이랑 이자를 같이 갚는 방식이에요? | "원리금을 함께 납부하는 방식" | 🟢 뜻은 맞음. 평가 기준(정확한 값 "원리금균등")이 엄격 |

**실제 문제는 2건**이고 4건은 평가 기준을 다듬어야 한다. 참고로 Base는 같은 질문에서 "연체 기록 삭제는 **가능합니다**", "부모님 명의 대출은 **확인이 가능합니다**"처럼 더 심각하게 지어냈지만, 자동 검사 패턴에 걸리지 않아 점수에 드러나지 않았다. **자동 지표만으로는 부족하고 사람 평가가 꼭 필요한 이유다.**

### 3-2. 결론

| 판단 기준 (EVALUATION.md) | 결과 |
|---|---|
| Base보다 규칙 준수가 좋아졌는가 | ✅ 64% → 86% |
| 기존 능력이 손상되지 않았는가 | ✅ 검증 통과 유지, 금지 표현 감소, 톤 개선 |
| 금지 표현이 늘지 않았는가 | ✅ 0% 유지 |
| 사람이 보아도 좋은가 | ⏳ 미실시 |

→ **v03을 현재 최선 모델로 두고 조건부 채택.** 사람 평가와 아래 수정 방안 1·2를 거친 뒤 최종 채택한다.

## 4. 남은 문제와 수정 방안

### 4-1. 지금 확인된 문제

| # | 문제 | 수정 방안 | 규모 |
|---|---|---|---|
| 1 | **서비스 출력 검증이 즉시 불합격 유형을 거의 못 막음.** 서류 요건·처리 주장·개인정보 요구·"밤 11시" 같은 시각·은행/앱 이름·마크다운이 모두 통과함(직접 확인) | `validate.py`에 평가용 금지 표현과 "행동 약속" 검사를 옮기고, 숫자는 허용 목록(다음 납부일·연체 일수만)으로 바꾼다. 걸리면 기본 문장으로 대체. 모델 품질과 상관없는 **안전망** | 반나절 |
| 2 | v03이 "할 수 없다"고 단정하거나 "확인해 드리겠습니다"라고 약속함 | ① 1번 검증이 "드리겠습니다" 약속을 막는다. ② 직원 확인·다른 상품 템플릿에 "가능 여부는 상담원에게" 답을 늘려 재학습 | 템플릿 수정 + 재학습 30분 |
| 3 | 기본 문장에 납부 방법이 없음(PRD 사용자 스토리 2) | 연체일 때 "납부 방법은 {가상계좌 입금}입니다" 추가 | 짧음 |
| 4 | 모델 호출이 실패하면(Ollama 꺼짐·시간 초과) 에이전트가 오류를 냄 | 실패 시 기본 문장으로 대체 | 짧음 |
| 5 | 평가 기준이 좋은 답도 틀렸다고 봄(4건) | 확정 요청은 "처리 불가 안내"도 인정, 연체 일수 질문은 일수만 있어도 인정, 상환 방식은 뜻이 같으면 인정 | 짧음 |
| 6 | AI Hub 110건이 사람 검수 전 | `review.py`로 검수 → 04 재생성 → 재학습(v04) | 검수 30~40분 |

### 4-2. 다음 학습 결과가 좋지 않을 때 대응표

| 증상 | 가능한 원인 | 대응 |
|---|---|---|
| 규칙 준수가 Base보다 낮다 | AI Hub 정답이 통화 말투를 가르친다 | AI Hub 비중을 줄이고(검수 통과분만) 합성 비중을 늘린다 |
| 슬롯을 안 쓰거나 이자 정보를 무시한다 | 학습 정답이 이자 정보를 쓰지 않는다 | 합성 템플릿에 해당 유형 답을 늘린다. 학습 데이터 형식이 `prompt.py`와 같은지 `--dry-run`으로 확인 |
| 답 앞에 `<think>`·`<tool_call>` 같은 태그 | 학습·추론 템플릿 불일치 | `--dry-run`과 `chat_template.jinja` 확인(v01 사례) |
| 같은 문장만 반복한다 / eval loss가 오른다 | 합성 문장을 외움(과적합) | epoch 1로 줄이거나 학습률 5e-5, 템플릿 답 표현을 늘린다 |
| 새 고객에서만 틀린다 | 데모 값을 외움 | 합성 조회값의 다양성(연체 일수·방식)을 넓힌다 |
| 금리·서류·시각을 지어낸다 | 데이터에 남은 표현 또는 Base 성향 | 제외 규칙 보강 + 서비스 출력 검증(4-1의 1번)으로 차단 |
| 계속 Base보다 못하다 | 파인튜닝 이득이 작다 | Base + 시스템 프롬프트 보강 + 출력 검증으로 운영하고, 파인튜닝은 말투만 다듬는 약한 설정으로 되돌린다 |
