# 학습 데이터 가이드: cs-interest

> `cs-interest` QLoRA 학습 자료에 무엇을 넣고 어떤 형식으로 만드는지 정리한다. 생성 코드는 `backend/training/interest/prepare.py`(AI Hub 정제), 학습은 `train.py`다. 형식의 기준은 `backend/app/agents/interest/prompt.py`이고, 정답의 기준은 `validate.py`다(INT-004).

## 1. 형식: 추론 입력과 똑같이

JSONL, 한 줄에 대화 1개. `prepare.py` 출력과 같은 형식이다.

```json
{"source_id": "...", "qa_id": "...", "messages": [
  {"role": "system", "content": "<prompt.SYSTEM_PROMPT>"},
  {"role": "user", "content": "(이전 턴이 있으면) 이전 질문"},
  {"role": "assistant", "content": "(이전 턴이 있으면) 이전 답변"},
  {"role": "user", "content": "고객 질문\n이자 정보: 종류=주택담보대출, 상환 방식=원리금균등, 금리 방식=고정, 납부 방법=가상계좌 입금, 다음 납부일=2026-10-25, 연체 여부=연체 중, 연체 일수=12\n사용할 수 있는 슬롯: {{loan_label}}, {{interest_due}}, {{overdue_amount}}"},
  {"role": "assistant", "content": "모범 답변 ← 학습 대상"}
]}
```

- 시스템 프롬프트, `이자 정보:` 줄, `사용할 수 있는 슬롯:` 줄은 `prompt.build_messages()`로만 만든다. 손으로 쓰면 한 글자만 달라도 추론 입력과 어긋난다.
- 학습 대상(loss)은 마지막 assistant 턴 하나다. 이전 턴은 맥락이다(`train.to_prompt_completion`).
- 고객 문장의 금액·번호는 마스킹 토큰(`[금액_1]`, `[계좌번호_1]`)으로 넣는다. 추론 때도 마스킹된 문장이 들어온다(계약 4).
- 대출이 없는 고객(C001)은 코드가 모델 없이 고정 문장으로 답한다(INT-003). 학습 자료가 필요 없다.

## 2. 내용: 질문 유형 × 조회 상황

질문 유형마다 정상·연체 상황을 모두 채운다.

| 질문 유형 | 예시 질문 | 모범 답변이 할 일 | 비중 |
|---|---|---|---:|
| 이자 금액 | "이번 달 이자 얼마예요?" | 종류, 다음 납부일, `{{interest_due}}` | 20% |
| 납부일 | "이자 언제 빠져나가요?" | 다음 납부일. 금액은 필요할 때만 | 10% |
| 연체 여부 | "연체된 거 있어요?", "밀린 거 있나요" | 정상이면 연체 없음, 연체면 일수와 `{{overdue_amount}}` | 20% |
| 연체 대응 | "연체되면 어떻게 돼요?" | 연체 사실, 빠른 납부 권유, 구체 방법은 상담원 안내 | 10% |
| 이유 질문 | "이자가 왜 이렇게 많이 나왔어요?" | 조회 사실(연체 여부)로만 설명, 금리 계산은 상담원 안내 | 10% |
| **금리·이율** | "금리 몇 %예요?", "연체 가산금리는요?" | **수치 없이** 상담원 확인 안내 | 15% |
| **범위 밖 요청** | "금리 낮춰 주세요", "납부일 바꿔 주세요", "필요 서류가 뭐예요?" | 할 수 없음을 알리고 상담원 안내. 처리했다고 말하지 않음 | 10% |
| 후속 턴 | (앞 답변 뒤) "그럼 연체 금액은요?" | 이전 턴을 이어받아 짧게 답함 | 5% |

금리·이율과 범위 밖 요청에 약 4분의 1을 배정한다. 인수 즉시 불합격 조건(지어낸 금리·서류 요건·상품명)이 이 두 유형에서 나온다.

## 3. 모범 답변 기준

| 할 것 | 하지 말 것 |
|---|---|
| 존댓말, 2~4문장, 질문에 바로 답함 | "고객님께서는 ~하고자 하셨습니다" 같은 3인칭 요약체 |
| 금액은 슬롯만 사용 | 금액 숫자, `[금액_1]` 같은 마스킹 토큰 |
| 날짜·일수는 `이자 정보` 줄의 값만 사용 | "밤 11시까지", "3영업일" 같은 없는 시각·기간 |
| 대출 종류는 `{{loan_label}}` 또는 `이자 정보`의 종류 | "청약 담보 대출", 은행명, 앱·메뉴 이름 |
| 모르는 것은 "상담원에게 확인해 주세요" | 금리 %, 가산 이율, 서류 목록, 수수료 |
| 연체 상태를 정확히 전달 | 정상 고객에게 연체 언급, 연체 고객에게 "문제없음" |
| 할 수 없는 일은 안내만 | "처리해 드렸습니다", "적용되었습니다", "등록되었습니다" |

모든 모범 답변은 `validate.is_valid`를 통과해야 한다. 통과하지 못하는 답을 학습하면 추론 때 기본 문장으로 대체되어 학습 효과가 없다.

예시(연체 고객, 이유 질문):
```
user: 대출 이자가 왜 이렇게 많이 나왔어요?
      이자 정보: 종류=주택담보대출, 상환 방식=원리금균등, 금리 방식=고정, 납부 방법=가상계좌 입금, 다음 납부일=2026-10-25, 연체 여부=연체 중, 연체 일수=12
      사용할 수 있는 슬롯: {{loan_label}}, {{interest_due}}, {{overdue_amount}}
assistant: 현재 {{loan_label}}이 12일 연체된 상태로, 연체 금액 {{overdue_amount}}이 남아 있습니다.
           다음 납부일인 2026-10-25에 납부하실 이자는 {{interest_due}}입니다.
           적용 금리나 연체 이자 계산 방식은 상담원에게 확인해 주세요.
```

## 4. 다양성

- 질문 말투: 정중체·반말("이자 얼마야")·짧은 질문·오타·두 가지를 한 번에 묻는 질문을 섞는다.
- `이자 정보` 값: 대출 종류(신용대출·주택담보대출·전세자금대출 등 일반 명칭), 납부일, 연체 일수(1~90일)를 바꾼다. 데모 값(C002·C003)만 외우지 않게 한다.
- 답변 문장: 같은 유형이어도 표현을 3~5가지로 돌린다.
- 정상:연체는 대략 1:1로 맞춘다. 현재 AI Hub 정제본은 연체 샘플이 2건뿐이다.

## 5. 양과 구성

| 출처 | 역할 | 권장 양 |
|---|---|---:|
| AI Hub 정제본(`prepare.py`) | 실제 상담 말투, 일반 안내 | 250~300건 |
| 합성 샘플(`prompt.py` + 질문·답변 템플릿) | 슬롯 사용, 금리 거절, 범위 밖 요청, 연체 상황 | 300~500건 |
| 합계 | | 550~800건 |

- 양보다 3번 기준을 어기는 샘플이 0건인 것이 중요하다.
- val·test 분할과 자체 점검 질문은 학습에 넣지 않는다. 합성 샘플에 점검 질문과 같은 문장을 쓰지 않는다.
- 합성 샘플은 공통 PRD 제약("데이터는 AI Hub 하나은행 부분만 사용")에 닿으므로 **팀 합의 후** 학습에 넣는다. 외부 사실 없이 mock 형식과 안내 문구만 쓴다는 점을 근거로 제안한다.

## 6. 현재 상태 (2026-09-28)

- AI Hub 정제본: 1,105건 중 347건(train 276 / val 28 / test 43, 임시 분할·마스킹). 슬롯 사용 5건, 연체 2건.
- 남은 문제: 이자 정보와 모순되는 상품명("청약 담보 대출"), 처리 완료 주장("적용되었습니다"), 3인칭 요약체가 정제본에 남아 있다. `prepare.py` 제외 규칙 보강이 필요하다.
- 합성 샘플: 미작성(팀 합의 대기).

## 만들기 전 체크리스트

- [ ] 형식 줄(시스템 프롬프트·이자 정보·슬롯)은 `prompt.py`로 만들었다
- [ ] 마지막 턴이 assistant이고, 모든 답변이 `validate.is_valid`를 통과한다
- [ ] 금리 %, 서류, 은행·앱 이름, 없는 시각·기간, 처리 완료 주장이 0건이다
- [ ] 2번 표의 유형이 모두 들어 있고, 정상·연체가 대략 1:1이다
- [ ] val·test와 점검 질문이 학습 셋과 겹치지 않는다
- [ ] 사람이 30건 이상 직접 읽어 확인했다
