# ADR: 이자/연체 에이전트

> 공통 결정(ADR-001~008)은 `docs/ADR.md`를 따른다.

### INT-001: 이자·연체 금액은 계산하지 않고 mock 값을 그대로 쓴다
**결정**: 이자·연체 금액은 mock 데이터에 미리 넣어 두고 슬롯으로 전달한다. 금리로 계산하는 로직은 만들지 않는다.
**이유**: MVP 목적은 조회 결과를 적은 단계로 보여주는 것이다. 계산 로직은 검증할 기준(실제 약정)이 없다.
**트레이드오프**: 데모 데이터는 서로 계산이 맞지 않을 수 있다. 화면에는 조회 값만 보여주므로 문제없다.

### INT-002: 금리·연체 이율은 답하지 않고 상담원 확인을 안내한다
**결정**: mock 데이터에 금리를 두지 않는다. 출력에 퍼센트 수치가 있으면 기본 문장으로 대체한다.
**이유**: 지어낸 금리 수치가 1건이라도 나오면 즉시 인수 불합격이다. "왜 많이 나왔나" 질문은 연체 여부 같은 조회 사실로만 설명한다.
**트레이드오프**: 이자가 늘어난 이유 설명이 제한적이다.

### INT-003: 조회 결과가 없으면 모델을 호출하지 않는다
**결정**: 대출·이자 내역이 없으면 고정 문장을 돌려준다.
**이유**: 없는 이자·연체를 지어낼 여지를 없앤다.
**트레이드오프**: 없음 안내 문장이 단조롭다.

### INT-004: 학습 정답은 추론 출력 검증을 통과한 것만 쓴다
**결정**: `training/interest/prepare.py`는 AI Hub output을 슬롯으로 바꾼 뒤 `validate.is_valid`를 통과한 샘플만 학습에 쓴다. 입력은 추론과 같은 `prompt.build_messages` 형식으로 만든다.
**이유**: 추론 때 기본 문장으로 대체될 문장(금액·금리 수치, 허용 밖 슬롯)을 학습하면 파인튜닝 효과가 대체로 사라진다. 학습과 추론의 입력 형식이 같아야 이자 정보·슬롯 줄을 제대로 쓴다.
**트레이드오프**: 원본 1,105건 중 약 3분의 1만 남고, 슬롯을 쓰는 샘플은 거의 없다. 슬롯 사용은 합성 샘플로 보강해야 한다(팀 합의 필요).
