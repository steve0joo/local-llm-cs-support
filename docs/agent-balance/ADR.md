# ADR: 잔액조회 에이전트

> 공통 결정(ADR-001~008)은 `docs/ADR.md`를 따른다.

### BAL-001: 조회 대상·의도 판단은 Python 코드, 문장 생성만 모델
**결정**: 계좌 매칭, 의도 판단(잔액·거래내역·일반 문의), 슬롯 값 생성은 코드로 한다. 모델은 슬롯 이름으로 상담 문장만 만든다.
**이유**: 원본 계좌번호와 금액이 모델에 닿지 않는다. 결과가 결정적이라 테스트하기 쉽다.
**트레이드오프**: 키워드 규칙이 놓치는 표현이 있을 수 있다. 자체 점검 셋에 넣어 보완한다.

### BAL-002: 출력 검증은 세 의도 모두 넓은 규칙으로, 실패하면 기본 문장으로 대체
**결정**: 잔액·거래내역·일반 문의(general) 응답 모두에 같은 규칙을 적용한다. 필수 슬롯 누락, 아라비아 숫자, `%`, 마스킹 토큰, 허용 밖 `{{슬롯}}`, 서류 키워드(서류·증명서·등본·재직·소득) 중 하나라도 있으면 그 의도의 기본 문장으로 대체한다. general의 기본 문장은 "해당 내용은 정확한 안내를 위해 상담원에게 확인해 주세요."이고, general은 허용 슬롯이 없다(세부 규칙은 ARCHITECTURE "출력 검증").
**이유**: 잔액 화면 인수 기준(모델은 `{{balance}}` 생성, 화면에 실제 금액)과 "지어낸 사실 0건"을 모델 품질과 상관없이 보장한다. 금액 형태의 숫자만 막으면 지어낸 기간·건수·금리를 놓친다. 슬롯이 없는 general 응답도 금리·서류 요건을 지어낼 수 있어 같은 규칙이 필요하다.
**LN-004와의 의도된 차이**: 대출 영역(LN-004)은 마스킹 토큰을 숫자 검사에서 빼고 "서류"라는 일반 단어를 허용한다. 잔액조회는 둘 다 대체한다. 잔액·거래내역 답변에는 마스킹 토큰이나 서류 안내가 필요한 경우가 없어서, 걸리면 지어냈거나 입력을 되풀이한 것으로 본다.
**트레이드오프**: "최근 5건"처럼 정상 문장도 대체되는 과대 대체를 감수한다. 대체 문장은 단조롭다. 대체 빈도를 로그로 보고 학습 데이터를 보강한다.

### BAL-003: 계좌가 여러 개면 선택지로 되묻는다
**결정**: 대상 계좌를 정하지 못하면 계좌 라벨 버튼을 보여준다(`choice: "balance"`). 되묻기 문구는 의도와 상관없이 "어느 계좌를 조회할까요?" 하나다. 입력한 계좌번호가 본인 계좌가 아니면 모델을 부르지 않고 "입력하신 계좌번호로 조회되는 계좌가 없습니다. 어느 계좌를 조회할까요?"와 본인 계좌 전체 선택지를 준다(계좌가 1개여도).
**이유**: 타이핑 없이 한 번 눌러 끝낸다(적은 프로세스). 문구가 하나면 잔액·거래내역 어느 질문에서 되물어도 어색하지 않다. 턴 상한 숫자는 아직 미정이다(`docs/PRD.md` 확인 필요 — 현재 설계 최대 봇 응답 3회).
**트레이드오프**: 턴이 하나 늘어난다.

### BAL-004: 일반 문의는 general 분기로 모델이 안내하고, 의도 판단을 계좌 결정보다 먼저 한다
**결정**: 의도는 balance / transactions / general 3분기다. 절차 표현(어디서·어떻게·방법·절차)이 있고 조회 요청 표현(알려·보여·얼마)이 없으면 general이다. 흐름은 라벨 클릭 확인 → 의도 판단 → general이면 계좌 결정·되묻기·슬롯 없이 모델 안내 / 아니면 계좌 결정 → 슬롯 → 출력 검증 순서다. general도 라벨 클릭 확인을 위해 `get_accounts`는 호출하지만, 모델 입력에는 계좌 정보를 넣지 않는다.
**이유**: 사용자 스토리 5가 이 영역의 약속이고, PM 고정 질문에 일반 문의가 섞이면 인수 때 걸린다. 계좌 결정이 먼저면 계좌 2개 고객(C002)의 일반 문의가 계좌 되묻기로 빠진다.
**트레이드오프**: 키워드 규칙이라 "잔액 알려주는 방법" 같은 표현은 조회로 판단된다. 자체 점검 셋으로 단어 목록을 늘린다.

### BAL-005: 순수 함수는 plain dict까지, handle()은 cherry-pick 발판 위에서 (2026-09-29 변경)
**결정**: mock API·계좌 결정·의도 판단·프롬프트 구성·출력 검증은 모델 없이 도는 순수 함수로 만든다. 계좌 결정 함수는 `AgentReply`가 아니라 plain dict(`{"account": ...}` 또는 `{"text": ..., "options": [...]}`)를 돌려주고, `AgentReply` 포장은 `BalanceAgent.handle()` 안에서만 한다. `handle()`과 `__init__.py` export는 팀원C의 스캐폴드·`llm`·`agents/base.py` 커밋(`a43c70a`·`e290476`·`6ed6cce`)을 `git cherry-pick -x`로 수정 없이 들여온 임시 발판 위에서 만든다. 발판은 팀원C의 feat-router가 main에 들어오면 그대로 대체된다.
**변경 사유(2026-09-29)**: 스텁이 main에 오기를 기다리면 `handle()` 흐름 테스트가 계속 밀려서, 임시 타입을 만들지 않고 팀원C 원본 커밋을 그대로 쓰는 방식으로 앞당겼다.
**이유**: 계약 3 타입은 팀원C 소유다. 로컬에 임시 타입을 만들면 스텁 병합 때 충돌하고 계약이 두 벌이 된다. 원본 커밋을 수정 없이 들여오면 계약은 한 벌이다.
**예외**: 발판 파일은 수정하지 않는다. 예외는 `app/agents/balance/__init__.py`(스텁 → 실제 export)와 `tests/router/test_base.py`(스텁 전용 검사에서 balance 제외) 둘뿐이다(ARCHITECTURE "알려진 한계").
**트레이드오프**: 발판 커밋 3개가 이 브랜치에 중복으로 들어온다. balance PR은 feat-router 스캐폴드가 main에 들어간 뒤 올리고, 병합 충돌은 위 예외 두 파일에서만 난다고 본다. PM 고정 질문 인수는 여전히 모델이 온 뒤로 밀린다.
