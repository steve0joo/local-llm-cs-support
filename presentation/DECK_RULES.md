## 6. 상태 배지 (준비 방법 표시)

| 배지 | 색 | 뜻 |
|---|---|---|
| 문서 기반 | 청록 | 프로젝트 md 문서만으로 채울 수 있음 |
| 팀원 지표 필요 | 주황 | 담당 팀원이 수치·결과를 넣어야 함 |
| 캡처 필요 | 보라 | 화면 캡처·영상이 필요함 |
| 조사 필요 | 파랑 | 프로젝트 밖 자료(마켓 리서치 등)가 필요함 |

- 배지는 장 단위로 하나. 자리 상자 단위로는 상자 색으로 구분함(아래 7절)

## 7. 자리 상자 규칙

- 모양: 둥근 사각형, 점선 테두리 1pt, 가운데 정렬 텍스트
- 텍스트: 굵은 라벨(무엇이 들어가는가) + 회색 설명(어떤 내용·예시인가)
- 색: 문서로 채우는 상자는 회색(`F1F5F9`). 팀원 지표·캡처·조사가 필요한 상자는 해당 배지의 옅은 색 배경 + 진한 색 점선
- 원칙: **뼈대 단계에서는 데이터를 넣지 않는다.** 페이지 구성을 먼저 확정하고 데이터를 채운다

## 8. 레이아웃 패턴

|---|---|
| 카드 3개 + 아래 넓은 상자 | 3 개발 의도 |

## 9. 섹션 구성과 시간 규칙

| 섹션 | 페이지 | 장 수 | 시간 | 장당 시간 |
|---|---|---|---|---|
| 표지 · 목차 | 1–2 | 2 | 0:20 | 0:10 |
| 01 배경과 목표 | 3–6 | 4 | 1:40 | 0:25 |
| 02 시스템 설계 (가안) | 7–13 | 7 | 2:20 | 0:20 |
| 03 모델 학습과 평가 | 14–18 | 5 | 3:20 | 0:30~0:50 |
| 04 데모 | 19 | 1 | 2:30 | 라이브 시연 |
| 05 회고 | 20–21 | 2 | 0:50 | 0:25 |
| Q&A · 감사합니다 | 22–23 | 2 | 시간 외 | — |
| **합계** | | **23** | **11:00** | 발표 8:30 + 데모 2:30 |

- 섹션별 최소 요건: 01은 4장 이상(개발 의도 · 서비스 정의 · 서비스 개요 · 마켓 리서치), 02는 7장 이내, 04는 첫 화면 이미지 한 장, 05는 분석 → 개발 방향 순서
- 03은 UX 플로우 → 프론트엔드 → 모델 4종 개요 → 대표 모델 1종 상세 순서. 대표 모델은 지표가 가장 잘 나온 모델 하나를 예시로 골라 자세히 설명함 (현재 cs-interest)
- 지표가 많이 들어가는 장(16, 18)에 시간을 더 준다

## 10. 발표자 노트 규칙

모든 콘텐츠 장에 노트를 넣는다. 노트에는 다음을 적는다.

- **근거:** 내용의 출처인 프로젝트 문서 경로 (예: `docs/PRD.md 인수 기준`)
- **말할 것:** 발표 때 짚을 포인트
- **팀원 추가 / 준비:** 채워야 할 지표나 캡처 (해당 장만)

## 11. 데이터·파일 운영 규칙

- 수치 출처: 평가 결과 원본(`backend/training/**/outputs/`)과 AI Hub 데이터는 gitignore 대상이다. 슬라이드에는 링크 대신 **수치를 직접 적는다**
- 금지: AI Hub 데이터 원문 인용(제3자 제공 금지), 실제 은행명·상품명 표기
- 작업 폴더: `presentation/` (작성자 전용. 최종본만 나중에 git에 포함)
- 버전 관리: 구성을 크게 바꾸기 전에 `backup/`에 사본을 남긴다 (`deck_skeleton_v1.pptx` = v1, 15장 구성)
- 문서 버전은 표지에 표기한다 (현재 v0.2)
