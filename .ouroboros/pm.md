# 로컬 LLM 은행 상담 보조 AI 어시스턴트 (MVP)

*Created At: 2026-09-28T02:38:46.752185+00:00*

## Goal

AI Hub 71926 금융분야 고객상담 데이터(은행/하나은행 부분)로 파인튜닝한 로컬 양자화 오픈 모델(Qwen 등)을 사용해, 고객의 첫 상담 메시지를 주제 분류하여 3개 전문 에이전트로 라우팅하고, 개인정보를 모델에 노출하지 않으면서 기존 챗봇보다 전문적인 답변과 더 적은 프로세스로 상담을 마칠 수 있게 하는 챗봇 MVP를 만든다.

## User Stories

1. **As a** 은행 고객, **I want to** 챗봇에 '내 잔액 얼마야?'처럼 한 번 문의하면 가상 잔액/거래내역 API를 통해 실제 금액이 채워진 답변을 받는다, **so that** 메뉴 탐색이나 여러 단계 없이 적은 프로세스로 조회 업무를 끝낼 수 있다.
2. **As a** 은행 고객, **I want to** 대출 만기/연장/조회 관련 문의를 대출 전문 에이전트에게 전문적인 한국어 존댓말 상담 답변으로 받는다, **so that** 일반 챗봇의 얕은 답변 대신 주제 전문 답변을 받아 상담 피로가 줄어든다.
3. **As a** 은행 고객, **I want to** 이자/연체금액 관련 문의를 해당 전문 에이전트에게 답변받는다, **so that** 연체·이자 궁금증을 상담원 연결 없이 즉시 해소한다.
4. **As a** 은행 고객, **I want to** 문의가 두 주제(예: 대출 잔액 + 이자)에 걸쳐 모호할 때 '어느 쪽을 먼저 도와드릴까요?' 확인 질문을 받는다, **so that** 엉뚱한 에이전트로 보내져 다시 설명하는 일을 피한다.
5. **As a** 은행 고객, **I want to** 지원하지 않는 주제(자동이체조회, 착오송금, 만기·연장/해지·수신, 한도, 부수거래금리감면, 환전)로 문의하면 미지원 안내와 상담원 연결 안내를 받는다, **so that** 잘못된 답변으로 시간을 낭비하지 않고 바로 올바른 창구로 이동한다.
6. **As a** 은행 고객 (개인정보 보호 관점), **I want to** 계좌번호·주민번호 등을 입력해도 해당 값이 모델에 전달되지 않는다, **so that** 민감정보가 LLM에 노출되지 않는다.
7. **As a** PM (인수 담당), **I want to** 고정 시나리오 셋을 직접 입력해 라우팅 결과·답변 품질·모델 입력 로그를 직접 확인한다, **so that** 자동 지표 없이도 인수 합격/불합격을 스스로 판정할 수 있다.
8. **As a** 개발자, **I want to** Windows RTX 4060 노트북 한 대에서 전처리·파인튜닝·시연을 모두 수행하고, 산출 모델을 macOS에서도 로컬 추론으로 구동한다, **so that** 국외 클라우드 학습 합의 없이 데이터셋 이용조건을 준수하며 개발·시연할 수 있다.

## Constraints

- 세부(전문) 에이전트는 3개만 만든다: 거래내역/잔액조회, 대출문의(만기/연장/조회 등), 이자/연체금액. 각 에이전트는 한 주제만 담당한다
- MVP이므로 오버엔지니어링하지 않고 간단하게 만든다
- AI 모델은 오픈 모델(Qwen 등)을 로컬 모델로 양자화 파인튜닝한다. 라우터와 3개 세부 에이전트 모두 로컬 모델
- UI는 챗봇 인터페이스여야 한다
- API와 고객 데이터는 mockup(가상 API/가상 데이터)으로 만든다
- 고객 개인정보는 모델에게 전달되지 않도록 마스킹한다: 주민등록번호, 카드번호, 계좌번호, 전화번호, 주소, 금액(잔액·대출 원금) 필수 마스킹
- 가상 API가 반환한 실제 값(잔액 등)은 모델에 전달하지 않는다. 모델은 자리표시자만 다루고 실제 값은 최종 화면에서만 치환한다
- 학습·시연 장비: Windows 64비트(x64) 노트북 — Intel Core i7-13620H, RAM 32GB, NVIDIA RTX 4060 Laptop GPU(VRAM 8GB), 저장소 477GB 중 195GB 사용. 파인튜닝과 시연은 같은 이 장비에서 수행
- 데모 Mac 사양: Apple M4 Pro, 통합메모리 24GB. Mac에서도 모델 추론까지 전부 로컬로 동작해야 한다 (Windows가 모델을 서빙하는 원격 구성은 불인정)
- 데이터셋은 AI Hub 71926 '금융분야 고객상담 데이터' 중 은행(하나은행) 데이터만 사용. 한국어 텍스트, JSON. 원천 32,998건 / 라벨링 50,000건
- 데이터셋 이용조건: 학습용 사용 및 출처 표시, 제3자 제공 금지, 국외 클라우드 학습 시 별도 합의 필요 (따라서 로컬 장비 한계가 모델 크기를 좌우)
- 답변 톤은 한국어 존댓말 상담 톤이어야 한다
- 모르는 내용은 지어내지 않고 상담원 연결을 안내해야 한다
- 9개 주제를 3개 묶음으로 전부 나눠 담지 않는다

## Success Criteria

1. 전문 에이전트 3개가 각각 거래내역/잔액조회, 대출문의(만기/연장/조회 등), 이자/연체금액 한 주제씩만 담당하며 동작한다
2. 나머지 6개 주제(자동이체조회, 중계요청/착오송금, 만기·연장/해지·수신, 금융거래한도/비대면한도계좌, 부수거래금리감면, 환전문의)로 분류된 문의에 대해 '해당 주제는 아직 지원하지 않습니다' 안내 후 상담원 연결을 안내한다
3. PM이 작성한 고정 테스트 문의 셋에서 올바른 전문 에이전트 또는 올바른 미지원 안내로 라우팅된 비율이 90% 이상이다
4. 두 주제에 걸친 문의(예: '대출 잔액이랑 이자 얼마 남았어요?', '대출 이자가 왜 이렇게 많이 나왔어요?')는 임의로 한쪽에 라우팅하지 않고 고객에게 '어느 쪽을 먼저 도와드릴까요?'와 같은 확인 질문을 되묻는다. 한쪽으로만 보내면 불합격
5. 모델 도달 전 주민등록번호, 카드번호, 계좌번호, 전화번호, 주소, 금액(잔액·대출 원금)이 마스킹된다
6. PM이 고정 시나리오(예: '제 계좌 110-1234-5678이고 주민번호 900101-1234567인데 잔액 알려줘')를 입력한 뒤 모델 입력 로그를 직접 확인했을 때, 위 필수 마스킹 항목의 원본 값이 로그에 하나도 남아 있지 않다
7. '제 잔액 알려줘' 시나리오에서 모델은 금액을 모른 채 '현재 잔액은 [잔액]입니다' 형태의 자리표시자 문장을 생성하고, 앱이 가상 API 값을 그 자리에 치환하여 고객 화면에 실제 금액(예: 1,234,567원)이 보인다
8. 고객이 메시지를 보낸 뒤 첫 응답이 시작되기까지 10초 이내다. 이 기준은 Windows RTX 4060 노트북과 macOS(M4 Pro 24GB) 양쪽에 동일하게 적용한다
9. 인수 데모가 Windows RTX 4060 노트북과 macOS(M4 Pro 24GB) 양쪽에서 실행된다. macOS에서는 모델 추론까지 전부 로컬로 수행된다
10. 답변 품질 판정: PM이 에이전트당 고정 질문 10건, 총 30건의 답변을 직접 읽어 합격/불합격을 매기며, 27건(90%) 이상 통과해야 합격한다 (자동 유사도 점수 및 파인튜닝 전 기본 Qwen 모델과의 비교는 판정 기준으로 쓰지 않는다)
11. 한 건이 '통과'되려면 세 조건을 모두 만족한다: ① 질문에 맞는 주제를 다룬다 ② 사실을 지어내지 않는다(모르면 상담원 연결 안내) ③ 한국어 존댓말 상담 톤이다
12. 모델이 데이터셋에 없는 사실(구체적 금리 수치, 실제 상품명, 없는 서류 요건)을 지어내면 한 건이라도 즉시 인수 불합격이다
13. 챗봇 인터페이스 UI, 가상 API, 고객 데이터 mockup이 제공되고, 거래내역/잔액조회 시 가상 잔액 API를 호출해 값을 가져와 표시한다
14. 잔액조회·대출문의·이자/연체금액 세 주제 모두에 동일한 턴 상한 기준을 적용한다 (본인 확인 등 추가 단계로 첫 메시지부터 최종 답까지 3턴 이상 소요되는 것은 허용)

## Assumptions

- 데이터셋 실제 파일은 아직 다운로드·검증 전이며, 폴더 구조, JSON 타입, 공식 train/val/test 분할 유무가 미확인 상태다
- 라벨링 JSON의 qa_data는 배열로 보이지만 확정되지 않았다
- 데이터셋 요약의 학습 설계(4bit QLoRA + Qwen 채팅 템플릿, source_id 기준 분할, 주제별 개별 평가 등)는 제안이며 확정 사항이 아니다
- VRAM 8GB 제약상 소형 오픈 모델 + 4bit 양자화가 필요하다고 전제한다
- Mac에는 CUDA가 없으므로, Windows에서 학습한 양자화 모델을 Mac용 형식으로 별도 변환·검증하는 작업이 추가로 필요하다
- 3개 세부 에이전트와 라우터를 각각 별도 로컬 모델로 둘지, 하나의 파인튜닝 모델을 프롬프트로 분기할지는 MVP 단순성 원칙에 따라 개발자 판단으로 전제한다
- '기존 챗봇 서비스보다 전문적이고 고객이 상담 피로를 덜 느낀다'는 출시 후 PM이 후속으로 확인할 성과 목표이며, 인수 계약 조건은 라우팅 90%·품질 90%·환각 0건·첫 응답 10초·마스킹 로그 확인으로 대체된다
- 고객 실명은 필수 마스킹 항목으로 선택되지 않았으므로, MVP에서는 실명이 모델에 전달될 수 있다고 전제한다 (향후 정책 변경 가능)
- 확인 질문 1회는 앞서 정한 '3턴 이상 허용' 기준과 충돌하지 않는다는 PM의 판단을 전제한다
- 가상 API와 고객 데이터는 실제 은행 시스템 연동 없이 mockup으로만 구현된다
